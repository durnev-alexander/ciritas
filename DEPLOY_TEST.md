# CIRITAS v4 — тестовое размещение

Эта инструкция предназначена для первого рабочего прототипа. Рекомендуется разворачивать его отдельно от действующего сайта: на `test.ciritas.ru` или в каталоге `/newsite/`.

## 1. Требования к хостингу

- PHP 8.1+ (предпочтительно 8.2/8.3).
- Расширения PHP: `pdo_mysql`, `mbstring`, `session`.
- MySQL/MariaDB с доступом к существующей базе CIRITAS.
- Возможность отправки почты через PHP `mail()` — необязательно для запуска, но желательно для уведомлений.
- HTTPS рекомендуется до начала пользовательского тестирования.

## 2. Получение исходников

Использовать ветку:

```text
v4-orders
```

Не заменять действующий сайт до завершения проверки.

## 3. Локальная конфигурация

Скопировать:

```text
config/local.example.php -> config/local.php
```

В `config/local.php` указать реальные параметры БД и пути к существующим каталогам `Uploads` и `photos`.

`config/local.php` не должен попадать в Git.

Пример структуры:

```php
<?php
return [
    'db' => [
        'host' => 'localhost',
        'port' => 3306,
        'name' => 'DB_NAME',
        'user' => 'DB_USER',
        'password' => 'DB_PASSWORD',
        'charset' => 'latin1',
    ],
    'site' => [
        'base_url' => 'https://test.ciritas.ru',
        'uploads_path' => '/absolute/path/to/Uploads',
        'photos_path' => '/absolute/path/to/photos',
    ],
    'mail' => [
        'enabled' => true,
        'to' => 'orders@example.ru',
        'from' => 'site@example.ru',
    ],
];
```

После создания реального почтового пользователя заменить адреса-заглушки на фактические.

## 4. Администратор

В `config/local.php` или переменных окружения задать:

- `CIRITAS_ADMIN_USER`
- `CIRITAS_ADMIN_PASSWORD_HASH`

Хэш создаётся командой:

```bash
php -r "echo password_hash('YOUR_PASSWORD', PASSWORD_DEFAULT), PHP_EOL;"
```

Не хранить открытый пароль в Git.

## 5. Проверка окружения

После загрузки открыть:

```text
/admin-modern/system-check.php
```

Проверить:

- версию PHP;
- `PDO MySQL`;
- `mbstring`;
- соединение с БД;
- наличие `csOrders`, `cart`, `cart_items`, `csSettings`;
- доступность `Uploads` и `photos`.

Красные проверки необходимо исправить до оформления тестового заказа.

## 6. Критический тест

Пройти последовательно:

1. Главная страница открывается без ошибок.
2. Каталог продуктов показывает активные программы без групп.
3. Страница продукта открывается по старому адресу `product.php?id=...`.
4. Ссылки загрузок `download.php?id=...` работают.
5. Добавить одну лицензию в корзину.
6. Изменить количество.
7. Добавить вторую программу/лицензию.
8. Проверить итоговую сумму.
9. Проверить заказ на организацию.
10. Проверить заказ на физическое лицо.
11. Проверить Почту РФ и курьерскую доставку (+1000 ₽).
12. Если есть активные записи раздела 7 — проверить дополнительный товар/услугу.
13. Оформить заказ.
14. Проверить запись в `csOrders`.
15. Проверить `cart.IsOrdered` и состав `cart_items`.
16. Открыть заказ в `/admin-modern/orders.php` и `/admin-modern/order-view.php`.
17. Проверить уведомление по e-mail, если почта уже настроена.

## 7. Что нельзя делать на этом этапе

- Не импортировать старый `db/ciritas.sql` поверх рабочей базы.
- Не удалять старый `/admin/`.
- Не удалять действующие `Uploads` и `photos`.
- Не переключать основной домен на новую версию до прохождения критического теста.

## 8. После успешного теста

После проверки на реальной базе:

1. Исправить найденные несовместимости.
2. Перевести PR #1 из Draft в Ready for review.
3. Слить `v4-orders` в `main`.
4. Сделать резервную копию действующего сайта и БД.
5. Выполнить финальное переключение публичной части отдельно от старой админки.
